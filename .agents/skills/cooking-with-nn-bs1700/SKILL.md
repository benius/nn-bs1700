# Panasonic NN-BS1700 料理流程

## 核心原則

先給一套能照著操作的 NN-BS1700 流程，再補替代方案。把時間當作首輪起點；生肉、魚、蛋與剩食用中心溫度或完成狀態收尾。

每次都先完整讀取 [source-priority.md](references/source-priority.md)。嚴格按「實測食譜 → 101 → 102 → 901」的來源層級採用資料；後順位只能補前順位沒說的欄位。`references/recipe/` 是 NN-BS1700 食譜查找入口，不代表整個目錄都是最高順位；先讀相符檔案開頭的「資料性質」。不要把衝突值平均，也不要讓低順位資料靜默改寫實測值。

把本 `SKILL.md` 所在目錄視為 Skill 根目錄，從該目錄解析相對連結。若環境沒有 `rg`，改用可用的檔案搜尋或逐檔讀取工具；不要略過標示為「完整讀取」的資料。

## 單一設備邊界

只輸出 Panasonic NN-BS1700 的模式、功率、溫度、配件、層位、操作與安全限制。不要提供 IH 爐、瓦斯爐、電子鍋或其他設備的設定，也不要把其他設備的料理時間換算成 NN-BS1700 時間。

多個設備 Skill 同時啟用時：

1. 只負責分配給 NN-BS1700 的食材與步驟。
2. 其他設備的設定由對應 Skill 提供；主 agent 負責合併時間線與成品。
3. 不為了使用 NN-BS1700 而加入沒有必要的步驟；若其他設備更適合，可明說本設備不參與該段。
4. 完整跨設備食譜是 CulinaForge 輸出，不得存回本 Skill 的 `references/recipe/`。

## 解析 CulinaForge 食材提示

支援下列輸入結構：指定一個或多個 `$<agent skill name>`、用餐人數、餐點名稱、編號食材清單，以及「特別說明」。

先整理：

- 人數與餐點目標。
- 每項食材的名稱、品牌、份數、單份重量、總重與生鮮／冷藏／冷凍狀態。
- 肉魚的厚度、帶骨、填餡與厚薄是否均一。
- 使用者偏好的去骨、分切、先後下料、口感或禁用方式。

食材沒有重量時，依一般包裝、顆數或份量建立合理估算並明列假設，不要停下來要求補齊。若重量、厚度或包裝指示會實質影響 NN-BS1700 安全設定，採保守首輪起點並要求在指定檢查點驗收；不要把估算寫成包裝事實。

特別說明優先納入流程。若偏好與設備硬邊界、包裝指示或食品安全衝突，說明原因並提供最接近原意的安全替代方案。

## 判斷使用條件

辨識料理或主食材分類、起始狀態、重量、數量、最厚處厚度、帶骨或填餡、目標口感、配件與容器。湯品另確認液體量與起始溫度、容器容量、覆蓋方式及防溢空間。

使用者沒有交代狀態時，依食材名稱與保存描述作合理判斷；仍無法判斷時才列出生鮮、冷藏、冷凍選項。沒有份量時，採料理表份量；表格也沒寫時，明說以 1～2 人份、單層、不超載估算。來源只寫「一片」卻沒寫重量時，寫重量未註明，不自行製造寬泛區間。

## 查找料理

1. 先用料理名、主食材、狀態與目標搜尋 [食譜目錄](references/recipe/) 和 [source-priority.md](references/source-priority.md)。命中相符檔案時完整讀取；實測欄位採最高順位，整理或類比欄位只作首輪起點。
2. 到 [recipes-by-category.md](references/recipes-by-category.md) 查 102 的固定整理表。它不是 `recipe/` 的完整清單，不把新資料反向寫進 102 的原始範圍。
3. 看不懂 `M600`、`S100`、`O230-P`、`G2-U` 等縮寫時，完整讀取 [mode-codes.md](references/mode-codes.md)，並展開成面板可操作文字。
4. 同一道料理有多種目標時先匹配目標。找不到完全相同料理時，選同類、相同厚度、相近含水率與相同成品目標的條目，清楚標示「類比推算」。

可用 `rg -n '料理名|主食材' references/recipe references/source-priority.md references/recipes-by-category.md` 定位；需要核對整理值時，再搜尋 `references/source-101-*.md`、`references/source-102-*.md` 與 `references/source-901-*.md`。

## 套用狀態與厚度

完整讀取 [thickness-and-safety.md](references/thickness-and-safety.md) 後再調整肉魚：

- 1 cm 冷凍薄片可依表格半解凍後接冷藏流程。
- 2 cm 冷凍肉通常先半解凍或全解凍，再按冷藏流程並提早測溫。
- 3 cm、帶骨、填餡或凍結不均者先完全解凍，不只延長高溫烘烤。
- 冷凍整尾魚先完全解凍，再按相符的生鮮／冷藏設定烹調。
- 表面已深而中心不足時，降低溫度或以 300 W 蒸氣短段補中心，再用單面燒烤（上）短時恢復表面。
- 份量加倍時先把時間增加約 30%，不要直接翻倍；中途換位並多測一個冷點。

相符實測食譜或 101 已有明確時間時，保留它作第一個檢查點；厚度表只補解凍路徑、安全檢查、可能增量與例外處理。

## 處理湯品與燉煮

先完整讀取相符的 NN-BS1700 食譜，再確認生熟狀態、帶骨與否、肉塊厚度、液體量、液體起始溫度、容器容量及覆蓋方式。沒有相符食譜時，才用同類肉塊與相近含水率的 NN-BS1700 條目類比，並把自訂時間與水量寫成首輪起點。

- 冷凍帶骨肉、結塊或厚薄不均者先完全解凍；湯已煮滾不代表骨邊肉已達安全溫度。
- 微波煮湯使用深型微波安全玻璃或陶瓷容器，置於爐內中央，不放金屬配件；寬鬆覆蓋並留排氣縫，食材與湯汁合計不超過容器三分之二。
- 需要先煮滾再慢燉時，完整讀取 [appliance-operation.md](references/appliance-operation.md) 的「含湯料理與微波連動」。只有相符 NN-BS1700 來源支持時才套用分段功率。
- 分開判斷安全與軟嫩。中心未達標時短段補熱；已安全但仍太硬時，才依相符食譜使用較長的低功率燉煮增量。

## 選自動或手動

需要自動行程時完整讀取 [auto-vs-manual.md](references/auto-vs-manual.md)。只有料理名稱、份量、容器、配件與層位都和機器畫面一致時，才把自動行程列為首選。只報已核實編號；條件改動或找不到完全相同名稱時改用手動，完成後仍以熟度與中心溫度驗收。

## 決定配件、層位與預熱

完整讀取 [appliance-operation.md](references/appliance-operation.md) 以確認模式相容性：

- 純微波與 300 W 蒸氣不用方盤、雙面烤盤或其他金屬。
- 雙面燒烤與單面燒烤（下）含微波，只依指示使用原廠雙面烤盤，不加入其他金屬或鋁箔。
- 麵包、披薩、牛排與多數烘焙先預熱；時間從食物入爐後開始算。
- 一層烘烤用上層或下層，不把方盤放中層；兩層烘烤用上下層並留意換位。
- 蒸氣前加滿約 650 mL 新水、裝好收集盤；完成後避開熱蒸氣並擦乾爐內。
- 實測食譜指定不用預熱或指定層位時採實測值，但仍遵守模式與金屬配件硬邊界。

## 組成食譜答案

依序寫：食譜摘要與假設、食材準備、設備分工、配件與位置、同步時間線、NN-BS1700 分段操作、完成判定、補救方式及來源說明。每段寫出模式、功率或溫度、時間，以及翻面、攪拌、換位或加蒸氣時機。

多設備食譜中，把本 Skill 支持的數值標成 NN-BS1700 設定；一般料理知識補出的切法、調味、份量或時間明確標成「食譜設計／合理估算」，不得偽裝成原廠或實測值。

## 食譜檔案與暫存位置

在 CulinaForge repository 產生食譜檔案時：

1. Markdown、PDF、PNG 一律寫入 repository 根目錄的 `output/recipe-card/`。
2. 渲染、轉檔、下載或測試暫存資料一律寫入根目錄的 `tmp/`。
3. 第一次使用 `<餐點名稱>.<副檔名>`。若任一同名目標已存在，不覆蓋；三種格式共用同一本地時間，改名為 `<餐點名稱>-yyyymmdd-hhmmss-.<副檔名>`。
4. 例如 `番茄海鮮速拌細麵-收乾版-20260804-180559-.png`。
5. 完成檔案不得寫入 Skill 根目錄、`references/recipe/`、`document/` 或 `tmp/`。

## 處理失敗與清潔問題

遇到爆裂、過乾、未熟、外熟內冷、不上色、底部濕、受熱不均、U50、蒸氣弱、白粉、冒煙或異味時，完整讀取 [troubleshooting-cleaning.md](references/troubleshooting-cleaning.md)。先給立即處置，再說預防方式。

門、門封、爐內玻璃或電源線損壞，持續火花、異常大量蒸氣／焦味，或錯誤重複出現時，要求停用、拔除電源並聯絡 Panasonic 服務，不教拆機。
