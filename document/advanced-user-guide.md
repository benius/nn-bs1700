# CulinaForge 進階使用者指南

CulinaForge 把工作分成兩個階段：先將每台烹調設備的使用手冊整理成獨立 Agent Skill，再讓 agent 依食材提示同時使用一個或多個設備 Skill 產生專屬食譜。設備知識與食譜輸出必須分離：Skill 保存單一設備的能力與限制，完整跨設備食譜保存到 `output/recipe-card/`。

## 1. 由設備手冊建立 Agent Skill

每次只處理一台設備。即使一次提供多份手冊，也要按設備型號分組，為每台設備各建一個 Skill；不得建立同時包含兩台設備的 Skill。

建議目錄名稱採 `cooking-with-<model>`：

```text
.agents/skills/cooking-with-<model>/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    └── <由該設備手冊整理的參考文件>
```

### 建立提示範本

```text
請使用 skill-creator，依下列使用手冊建立一個烹調設備 Agent Skill。

設備品牌與型號：【品牌、完整型號】
使用手冊：【檔案路徑或附件】
Skill 名稱：【cooking-with-<model>】
輸出目錄：@.agents/skills

要求：
1. 一個 Skill 只包含這一台設備；不要加入其他設備的設定、手冊或食譜。
2. 將可重複查找的模式、功率或火力、時間上限、配件、容器、層位、鍋具、安全限制、清潔、故障碼與完成條件整理到 references/。
3. SKILL.md 保留來源邊界、查找流程、操作判斷與最後檢查，不要複製整份手冊。
4. 手冊沒有提供的料理時間、水量、份量或完成判定，標示為未提供；不可假稱原廠建議。
5. 讓 Skill 能在 CulinaForge 的食材提示中，僅負責本設備可執行的步驟與限制。
6. 更新 agents/openai.yaml，並驗證 Skill frontmatter、名稱、相對連結與介面資訊。
7. 不要把產生的完整食譜存進 Skill；食譜輸出另放 @output/recipe-card。
```

若手冊同時涵蓋多個相近機型，必須在 Skill 中指定預設機型，並在有差異的欄位明確分開；只有在所有操作條件完全共通時才能共用同一段資料。

## 2. 以一個或多個設備產生食譜

Codex 使用 `$skill-name` 明確指定 Skill。其他平台可改用 `/skill-name` 或自然語言；料理條件與輸出規則不變。

### 食材內容範本

```text
我有下列食材，推薦我使用 $<agent skill name 1> 與 $<agent skill name 2> 做一道 <實用人數> 人份的 <餐點名稱>：

1. <食材名稱 1> <份數> 份，每份 <重量> g/kg
2. <食材名稱 2> <份數> 份，每份 <重量> g/kg
3. <列出所有食材，格式如上 1>

特別說明：
<說明偏好或者指定的食材料理方式>
```

食材可寫品牌、保存狀態、包數、顆數、單份重量、總重、厚度、帶骨或已調理狀態。沒有重量時，agent 依一般份量估算並明列假設；若包裝指示會影響安全或時間，仍提醒使用者以包裝為準。

### 多設備分工規則

產生食譜時應依序完成：

1. 解析用餐人數、餐點名稱、所有食材與特別說明。
2. 對沒有重量的食材建立可計算的合理估算，不把估算寫成包裝事實。
3. 由每個 Skill 分別核對自己設備可用的模式、配件、火力與安全限制。
4. 依食材狀態、設備優勢與完成時間分配工作；不要為了使用所有設備而安排沒有必要的步驟。
5. 將可同時進行的工作合成時間線，清楚標示何時開始、轉段、檢查、保溫與組合。
6. 手冊沒有具名食譜時，可以用一般料理知識設計首輪時間、切法與水量，但必須標為「食譜設計／合理估算」，不得歸因於設備手冊。
7. 以中心溫度、質地、沸騰狀態或包裝要求驗收；提供短段補時與失敗修正。

## 3. 食譜答案與食譜卡內容

建議依下列結構輸出：

1. **食譜摘要**：餐點、人數、總時間與設備。
2. **食材盤點**：原始輸入、重量估算與未使用食材。
3. **設備分工**：每台設備負責的食材與目標。
4. **前置處理**：安全解凍、去骨、分切、容器與調味。
5. **同步時間線**：可平行步驟、等待點與組合順序。
6. **逐設備操作**：模式、功率或火力、時間、配件、位置與檢查點。
7. **完成判定與補救**：中心溫度、質地、濃度、上色與補時。
8. **來源說明**：區分手冊／實測支持與食譜設計估算。

特別說明是硬需求，但若和設備安全、包裝指示或食品安全衝突，應先說明衝突，再提出最接近原偏好的安全替代方案。

## 4. 輸出與暫存規則

所有完成的食譜檔案都放在：

```text
output/recipe-card/
```

適用格式包含 Markdown、PDF 與 PNG。三種格式應使用相同基礎檔名，並呈現一致的食材、步驟與數值。不得把完成檔案留在 `tmp/`、Skill 目錄、`document/` 或 repository 根目錄。

所有渲染中間檔、下載素材、轉檔結果、測試輸出與暫存程式資料都放在：

```text
tmp/
```

`tmp/` 已在 `.gitignore` 中設定為忽略，不會提交到 GitHub。

### 同名檔案處理

產生檔案前先檢查三種目標格式。若任一同名目標已存在，不得覆蓋；取得一次本地產生時間，讓同一組 Markdown、PDF、PNG 共用時間戳記：

```text
<基礎檔名>-yyyymmdd-hhmmss-.md
<基礎檔名>-yyyymmdd-hhmmss-.pdf
<基礎檔名>-yyyymmdd-hhmmss-.png
```

時間使用 CulinaForge 執行環境的本地時間。例如：

```text
番茄海鮮速拌細麵-收乾版-20260804-180559-.png
```

時間日期前有一個 `-`，日期與時間之間有一個 `-`，並依既定格式在副檔名前保留一個 `-`。

## 5. 驗證清單

建立或更新設備 Skill 後確認：

- Skill 目錄名稱與 frontmatter `name` 相同，只使用小寫字母、數字與連字號。
- 一個 Skill 只有一台設備，沒有混入其他設備設定或完整跨設備食譜。
- 設備數值可追溯到該 Skill 的 references，手冊未提供的欄位沒有被偽裝成原廠值。
- `agents/openai.yaml` 與 SKILL.md 的用途一致，且 Skill 驗證工具通過。

產生食譜後確認：

- 人數、食材、份量假設與特別說明都有處理。
- 每個設備步驟都由對應 Skill 核對，沒有跨設備複製設定。
- 生肉、魚、蛋、海鮮與剩食有完成判定；包裝食品保留包裝優先規則。
- Markdown、PDF、PNG 位於 `output/recipe-card/`，內容一致且沒有覆蓋舊檔。
- 所有中間檔只存在 `tmp/`。
